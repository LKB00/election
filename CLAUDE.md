# Notes for AI assistants

- Product: "Election", a place to see what people think about anything (fun/fan polls, not official, not legal elections). Owner is not a developer: explain in easy English. The plan for this direction is `docs/OPINIONS.md`.
- Stack: Next.js 15 (App Router) + TypeScript 6 (TypeScript 7 breaks Next 15) + Drizzle + Postgres. No `DATABASE_URL` means a local PGlite database in `.data/`.
- All poll and vote rules live in `src/lib/polls.ts`. One vote per voter is enforced by a unique index; keep it that way.
- Every poll is made by a person (owner, Oct 2026). The site never adds polls of its own: no seeded, sample or "starter" polls (the old ones are retired once by `src/db/retire.ts`). Templates are fine only when a person chooses them (ideas on Create, packs) and the poll is theirs.
- Hidden results must never leak: `getPoll` zeroes the numbers when `resultsVisible` is false.
- Look = **Arogya Line** (owner, Oct 2026: "make the Election website look visually like Arogya Line", repo LKB00/arogya-line): Figtree, warm off-white ground, white cards with thin warm borders and 18px corners, ink main button, soft indigo vote keys and selected states, Arogya's yellow as the brand and "you" colour, its pink / marigold / green signals, a light look and a dark look that follows the phone's setting (owner, Oct 2026; colours are tokens in `arogya.css`, the dark block only changes values: never hard-code a colour in a rule or component). It lives in `src/styles/arogya.css`, loaded last. Structure = the patricka (Good Bot, Bad Bot) markup/classes copied unchanged into `src/styles/gb/` (tot, today-card, daily-banner, games): do not edit gb/; Election-only layout goes in `src/styles/election.css`, look changes in `arogya.css`. Share images, the app icon and the phone's top bar use the same palette (`src/lib/palette.ts`; a test keeps it equal to `arogya.css`). Nothing hard-coded (owner, Oct 2026): size limits live in `src/lib/limits.ts`, India time and date locale in `src/lib/time.ts`, page titles and screen-reader labels in `i18n.ts`. Build screens from Arogya's blocks (`al-home` header, `al-block` titled sections with a count, `al-listcard`/`al-row` list rows, `al-hero` Up next card, `al-chip` status chips with icon + word) and its principles (one next step, colour never alone, every element earns its place); see `docs/DESIGN.md`.
- Opinions rule: every poll works like a simple, fair vote (secret ballot, one vote each, results after you vote, the inked finger as our signature, "Guess the crowd"). The full booth ritual (EVM beep, VVPAT slip, voter ID, counting day, "Result declared") is **Election mode**: on for politics polls, a choice for creators, off otherwise. Never use the words "exit poll" in the product (legal risk, RP Act s.126A). No quiz/game parts from patricka: no steppers, score bubbles, points, levels, trophies or streaks; never money, coins or prizes.
- Every element needs a job and a priority (P1/P2/P3). Read and update `docs/DESIGN.md` before changing any screen. One P1 per screen; yellow (`--lime`, Arogya's brand yellow) = "you / your progress"; ink button = the one main action.
- All interface text lives in `src/lib/i18n.ts` (English + Hindi + Hinglish). Never hard-code UI text in components; add a key to all three languages. Share images are English or Hinglish (the image renderer cannot shape Hindi).
- Fonts are bundled (fontsource), not Google Fonts, so screenshots in the sandbox match real phones.
- Tests run on PGlite; also run them on real Postgres with TEST_DATABASE_URL (it caught Date/precision bugs).
- Before pushing run `npm run check`.
- Vercel is on the free plan, which limits builds per day. Work branches (`claude/**`) do not build previews (`vercel.json`, `git.deploymentEnabled`), so only a merge to main builds. Push once per finished piece of work; when the owner says "make live": run `npm run check` (and the Postgres tests), push, open the PR, merge it, then confirm the main deployment and the live site (there is no preview check to wait for) (owner, Oct 2026).
- Anything only the owner can do (settings, accounts, decisions, daily jobs) goes in `docs/OWNER_TODO.md` in easy English; mention it when it changes.
- Develop on branch `claude/stoic-volta-r2mir5`. Do not open a PR unless asked.
